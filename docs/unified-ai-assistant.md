# PC AI 助手统一改写工作流

实现日期：2026-09-19；2026-09-26 调整为不新增表方案，并同步本地主线 f09353e 的模型接口与账号身份修复。前端与 Java 埋点后端分别位于独立 worktree，同名分支 `codex/unified-ai-assistant`。本次未部署生产环境；本功能无需数据库迁移。

## 用户体验

- PC 模块「AI润色」「AI帮我写」保留原位置，点击后进入现有编辑工作区中的 AI 助手，显示所选经历与任务。打开面板不扣额度。
- 内容充分就改写，不知道怎么写或事实不清楚时每轮问 1–3 个日常问题；选项填入输入框，由用户提交，不默认替用户认定事实。
- 简历与用户明确自述是事实来源；JD、例文与模型以前的建议不是用户事实。模型改写后再进行独立语义复核，数字还经过额外差异检查。职责、能力和成果存疑时只显示确认问题。
- 默认显示中文文字差异，可切换完整结果。支持应用这一处、保留原文、撤销本次修改；点击卡片标题可定位编辑区对应内容。
- 直接修改只认本条用户明确授权，且必须通过事实检查。引用、条件句与推荐问题点击不授权直接修改；批量直接应用合成一个撤销步骤。
- 生成后若目标内容被手动更改或删除，不覆盖新内容。撤销只还原对应段落，不覆盖其它手动编辑；目标后来有改动则提示使用编辑历史。
- 正常回答完成后显示 2–3 条相关后续问题，沿用当前任务上下文，不另调模型生成选项，不额外扣次。
- 旧版聊天仅保留只读历史，独立全文优化入口已移除。新版历史单独保存，旧版历史可从面板进入；恢复历史不会重新执行修改。移动端模块入口继续走原界面。

## 实现结构

`src/lib/ai/unified/`：任务、输出协议、事实规则、服务端处理及现有额度消费。

`src/components/ai-chat/unified-assistant.tsx`：统一交互界面。差异计算与修改事务位于同目录的 unified-changes.ts；沿用现有 Zustand 简历、撤销历史与更新机制。

`POST /next-api/ai/chat/task`：输入包含 task、requestId、text、resumeData、turns 和 fromFollowup。turns 来自当前浏览器的本地会话，只传用户消息、助手回答、问题及建议正文；不传执行授权、已扣次标记、修改前快照或审核通过标记。接口校验历史结构和长度，并从登录态确定账号及会员状态。任务 ID 仅用于本地分组和埋点，不再代表服务端持久化任务或授权凭据。

历史是客户端提供的上下文，不是经过服务端认证的记录。历史用户自述与当前简历用于核对事实，历史助手建议不作为事实依据；自动修改授权仍只判断本次用户消息。服务端根据本次目标及模型路由确定额度类别，不信任客户端扣次标记。单个任务最多 60 轮，超限引导新建对话；完整请求限制 300,000 字符，不悄悄截断历史事实。

处理顺序：验证输入及身份 → 读取本次携带的本地历史 → 识别意图和缺失事实 → 需要追问则免费返回问题 → 按功能扣次 → 生成结果 → 事实复核 → 客户端保存结果、预览或在本次明确授权下应用。

2026-10-03 起，新版通过流式响应逐步展示纯文本草稿，并按实际处理阶段显示理解要求、生成草稿、核对事实。草稿标注“尚未完成事实核对”，只保存在当前组件状态，不提供应用按钮、不写入简历或对话历史。完整结果通过校验后替换草稿，沿用差异预览、事实确认、应用及撤销。停止、断流、超时或失败时清除临时草稿；失败不自动重新发送请求。

前端通过 `Accept: application/x-ndjson` 请求流式任务接口，服务端依次发送 progress、preview、result 或 error 事件。正文生成使用模型真实流式输出（约80ms合并更新一次），只提取用户可见的 answer / proposals 正文，不显示内部路由、推理或事实复核内容。意图判断和独立事实核对仍保留；修改完成前不会提前执行自动应用。未请求流式协议的调用方继续收到原 `{turn}` JSON。响应设置 `Cache-Control: no-cache, no-transform` 和 `X-Accel-Buffering: no`；部署后的代理/CDN仍需验证是否保留分片传输。此次验证见 [流式助手验收记录](ai-assistant-streaming-qa.md)。

## 数据与额度

不新增数据库表、字段、Redis 或其它持久化服务。Prisma schema 与当前主线一致，原新增建表迁移和服务端任务账本已删除。

- 本地 IndexedDB 保存最近 20 个任务及其对话、预览状态和撤销凭据；历史仅在当前浏览器可用，不跨设备同步。服务端不持久化任务对话或生成结果，但每次处理仍需接收相关内容并调用模型。
- 润色使用 `ai:polish-section`；帮我写使用 `ai:generate-section`；普通问答使用 `ai:editor-assist`。
- 任务内信息收集不扣生成额度；生成开始计一次，主动重新生成使用新请求ID再计一次。生成失败不自动退款，沿用开始计次口径。
- 前端发送期间禁止重复提交，不自动重试失败的 HTTP 请求。手动「重新生成（重新计次）」使用新请求 ID、当前简历和当前任务历史；显示上一请求若已开始生成可能已扣次的提示。停止请求也不能保证退回已消费额度。
- 没有服务端持久化的请求去重或结果重放；即使调用方重复提交相同 ID，也按独立请求处理。单次接口执行内部最多扣次一次，不将这一保障描述为跨请求幂等。
- 继续使用现有 User / UserQuota 表和原功能额度键。登录 unionid 与 Java userId 分开传递，经 syncUserIdentity 统一到已有账号；旧数字 ID 账号的额度只作为只读基线计入上限，不重复拷贝。数据库行锁串行化同账号额度更新。旧 AI 接口同一额度行的更新也改为锁内读取、按 JSON 键更新，避免新旧功能并发互相覆盖余额。
- 恢复本地历史不自动应用；只有当前活跃请求的完整响应可触发直接修改。客户端同时校验目标快照。
- 新增 `ai_assist_interaction` 的入口、开始、追问、预览、应用、保留、撤销、推荐问题、冲突、失败等行为统计；不上传简历正文。Java 白名单同时补齐原本缺失的四个 `ai_assist_*` 事件。

2026-09-26 埋点进一步升级为 schemaVersion=2：补齐实际可见曝光、逐条建议及推荐问题 ID、批量撤销关联、请求耗时、提交来源与失败分类；额度阻断不重复算失败。字段及使用率/采纳率口径详见 [AI 埋点说明](ai-analytics.md)。仍复用现有埋点表；管理员现有总览不等于 AI 专项漏斗看板。

## 推荐入口与真实信息补充（2026-10）

- 改稿完成后的推荐由程序生成：继续精简、解释差异、补充真实信息。模型输出的“是否有某项数据”等问句不再直接用作下一条用户消息。
- 补充入口先打开本地表单，服务规模、工具和用途、交付物都可留空，也可选择没有或暂不确定。打开、取消不调用模型；确认提交才重新润色。选择没有表示没有额外可补充的信息，不删除原文已有事实。
- 全文任务补充信息时选择对应段落，切换段落清空未提交内容，提交只润色该段。这个入口已确定动作和目标，省去路由模型调用，仍保留生成、事实复核、预览和手动应用。
- `messageSource` 区分用户回答与自动推荐。自动推荐、历史推荐示例不是事实证据；历史问题标题中的示例与数字也不作为用户回答。旧历史中的三类事实问题可打开补充表单。
- 补充提交沿用推荐点击的埋点关联，重试保留来源和段落。任何推荐入口均不能自动应用；是否计次由原有生成/追问规则决定。验证见 `docs/ai-assistant-followup-qa.md`。

## 全文优化接替旧版（2026-09）

- 编辑器顶部「简历检查」可直接启动全文优化，也可先检查再点击「预览全文优化建议」。岗位匹配的优化按钮也交给新版，默认预览。
- 全局助手支持「优化整份简历」。模块任务保持原范围，不静默跨模块修改。
- 显示每段有建议、建议保留、待确认、尚未检查、暂无正文。覆盖报告不代表姓名、联系方式、职位、日期或排版已自动修改。
- 安全建议可逐项应用/保留，也可勾选后批量应用。批量写入是一次原子操作，任一原文冲突则整组不写入；撤销共享回执的一组修改。其他段落的事实疑问不阻塞已经核对的建议。
- 检查报告/JD 放在 task.reviewNotes，不能作为用户事实证据；原文和用户自述仍是唯一事实来源。旧对话只读，不重放历史修改。
- 新版现为默认流程，不再依赖 NEXT_PUBLIC_UNIFIED_AI_ASSISTANT 开关。旧独立优化弹窗、面板、hook、prompt 和 POST /next-api/ai/optimize-resume 已删除。
- PC /editor 和其窄屏布局共享 EditorAiPanel；独立移动编辑页原本不调用旧全文优化 API，不额外添加入口。模块移动端原有写作行为不在本次调整范围。
- 全文优化一次生成计 ai:editor-assist；路由纯追问不扣次，预览/应用/撤销不扣次。简历检查与后续优化是两个独立请求，分别计次。独立 JD-match 工具也改用 ai:editor-assist，避免删除旧额度后失效。
- 删除前后端额度展示/配置中的 aiOptimizeResume。已有数据库历史用量保留，无新增表或迁移。旧浏览器缓存中的多余字段被正常忽略。
