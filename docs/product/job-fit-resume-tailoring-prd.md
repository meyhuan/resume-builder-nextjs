## 0. 文档范围与实施优先级

本文档定义“基于目标岗位一键生成定制简历”的轻量 MVP，包括 Dashboard 入口、岗位信息输入、AI 生成过程、完整简历 Diff 结果页，以及进入现有简历编辑器后的衔接。

本功能也是 [求职材料工作区 PRD](./job-search-workspace-prd.md) 中“岗位版本”的首期落地，但交互范围已经收敛：

- 本期不增加事实逐条确认。
- 本期不要求用户逐条接受或拒绝 AI 修改。
- AI 自动生成独立岗位版本，结果页集中解释改动。
- 用户不满意时直接进入现有编辑器修改。

如果本文档与《求职材料工作区 PRD》在岗位定制 MVP 的流程上冲突，以本文档为准；旧文档中的事实确认和逐条审核作为后续增强能力评估。

## 1. 产品定义

### 1.1 产品定位

岗位定制帮助用户基于一份基础简历和目标岗位 JD，一键生成更匹配该岗位的独立简历版本。

它不是另一个简历编辑器，也不是要求用户逐项审核的 AI 工作台。AI 负责完成分析、匹配和改写，结果页负责让用户看懂“最终简历、具体改动和下一步建议”，现有编辑器负责后续人工修改、排版与导出。

### 1.2 核心用户价值

- 少操作：从简历和 JD 到结果只需要一次主要提交。
- 看得懂：用户始终能阅读完整简历，而不是零散的建议列表。
- 有解释：每一处 AI 改动都能追溯到原文、优化后内容和原因。
- 不污染：岗位版本不会覆盖基础简历。
- 能继续：用户可直接进入现有编辑器修改和导出。

### 1.3 核心用户任务

> 当我准备投递一个具体岗位时，我希望 AI 根据 JD 自动优化现有简历，并清楚告诉我改了什么，让我快速检查后继续编辑或导出，而不是逐条处理大量建议。

## 2. 背景与问题

现有简历产品能够创建、导入、编辑和导出简历，但用户面对具体岗位时仍需自行完成以下高成本工作：

- 从长 JD 中识别关键职责和任职要求。
- 判断简历中的哪些经历与岗位相关。
- 将原有经历改写成招聘方容易识别的表达。
- 在保护关键履历事实的前提下，通过专业优化或冲刺增强补强岗位表达。
- 对比优化前后内容，确认 AI 没有改变关键事实。

竞品通常将匹配评分、建议、生成内容和编辑能力拆成多个步骤，容易造成流程过长、用户不知道下一步该做什么。本期应将流程压缩为：选择简历与岗位 → AI 自动生成 → 阅读完整结果与 Diff → 进入编辑器。

## 3. 产品目标与指标

### 3.1 产品目标

1. 用户能够从 Dashboard 或指定简历卡片进入独立岗位定制页面。
2. 用户提交基础简历和 JD 后，无需中途确认即可获得独立岗位版本。
3. 结果页同时展示匹配变化、AI 做了什么、完整优化简历和后续建议。
4. 用户能从结果页无缝进入现有编辑器完成修改、预览和 PDF 导出。
5. 基础简历、岗位版本和 Diff 具有稳定的可追溯关系。

### 3.2 首期衡量指标（建议，待评审）

| 指标 | 定义 | 首期目标 |
| --- | --- | --- |
| 定制启动率 | 进入岗位定制页后成功点击生成的用户占比 | ≥ 45% |
| 生成成功率 | 创建的任务中成功保存结果的占比 | ≥ 95% |
| 结果到编辑器转化率 | 查看结果后点击“进入编辑器”的用户占比 | ≥ 50% |
| 二次使用率 | 30 天内再次创建岗位版本的用户占比 | 作为基线观测 |
| 生成耗时 | 从提交到结果可用的 P90 | ≤ 45 秒，页面预期提示 20–30 秒 |
| 事实安全反馈率 | 用户反馈 AI 篡改或虚构事实的结果占比 | < 1% |

匹配分数不得作为 ATS 通过率或录用概率对外承诺。

## 4. 目标用户与场景

### 4.1 主要用户

- 已有一份基础简历，准备针对多个岗位投递的职场用户。
- 不熟悉 JD 拆解和简历关键词表达的应届生。
- 希望突出可迁移能力、但担心 AI 夸大的转岗用户。
- 临近投递截止时间，希望快速完成定制的用户。

### 4.2 典型场景

1. 用户在“我的简历”中找到一份简历，悬停后点击“针对岗位优化”。
2. 用户从侧边栏进入“岗位定制”，再选择一份基础简历。
3. 用户只有 PDF、Word 或文本简历，从岗位定制页直接导入后生成。
4. 用户查看结果，点击高亮了解 AI 修改原因，再进入编辑器微调。
5. 用户认为某处表达不合适，不在结果页逐条拒绝，而是在编辑器中直接修改。

## 5. 产品原则

### 5.1 一键优先

- 页面提供合理默认值。
- 用户可以忽略优化重点设置，直接生成。
- 生成过程中不插入事实确认、方案选择或逐条接受步骤。

### 5.2 完整上下文优先

- 结果页默认展示完整优化后简历。
- Diff 是完整简历上的解释层，而不是独立的改动清单页面。
- 未修改内容也必须正常显示，帮助用户判断整体阅读体验。

### 5.3 AI 可解释但不打断

- AI 改动默认高亮。
- 用户按需点击高亮查看原文、优化后内容和原因。
- 不强迫用户处理每一处改动。

### 5.4 基础简历不被覆盖

- 生成时锁定一份来源快照。
- 结果保存为新的岗位版本。
- 用户在岗位版本中的编辑不会反向修改基础简历。

### 5.5 完整可投递与内容来源可追踪

- 用户无需逐条确认事实和数字，生成结果不得出现占位符或半成品内容。
- 默认“专业优化”只写入已有事实和证据支持的可迁移能力。
- 用户可主动选择“冲刺增强”，允许 AI 补充相邻技能、职责和有依据的合理约数/区间；结果页轻量标记推断数量，但不阻止继续编辑或投递。
- 姓名、联系方式、公司、学校、既往职位、日期、学历、证书、奖项和专利始终受保护。
- 营收、GMV、预算、融资、排名、团队人数和客户数量等可外部核验事实不得由 AI 估算。

## 6. 命名与信息架构

### 6.1 用户可见命名

| 场景 | 名称 |
| --- | --- |
| 侧边栏入口 | 岗位定制 |
| 独立页面主标题 | 为目标岗位优化简历 |
| 简历卡片快捷操作 | 针对岗位优化 |
| 生成按钮 | 生成岗位定制版 |
| 结果页主操作 | 进入编辑器 |
| 结果页重新开始 | 重新定制 |

避免同时使用“职位匹配”“AI 润色”“简历诊断”“岗位优化”等多个同级功能名，防止用户误以为需要重复执行多个工具。

### 6.2 页面归属与建议路由

```text
/dashboard
├── 我的简历
├── 顶部基础简历快捷操作
└── 简历卡片“针对岗位优化”

/dashboard/job-fit
├── 岗位定制输入
└── 定制记录入口（P1）

/dashboard/job-fit/[taskId]/processing
└── AI 生成进度

/dashboard/job-fit/[taskId]/result
└── 匹配评分 + 完整简历 Diff

/editor/[resumeId]
└── 现有真实简历编辑器与导出
```

具体路由可由技术方案调整，但岗位定制必须是带应用侧边栏的独立页面，不能使用 Dashboard 抽屉。

## 7. 范围

### 7.1 V1 必须包含

- Dashboard 侧边栏“岗位定制”入口。
- 简历卡片 Hover 快捷入口。
- 已有简历、文件导入、文本粘贴三种来源模式。
- 公司、岗位名称和 JD 输入。
- 可忽略的优化重点设置与合理默认值。
- “专业优化 / 冲刺增强”两种优化方式，默认专业优化。
- AI 处理进度和失败重试。
- 原始匹配分、优化后匹配分和提升值。
- “AI 已完成”与“进一步提升建议”的清晰区分。
- 完整优化后简历、原简历切换和 Diff 高亮。
- 点击高亮查看原文、优化后内容和修改原因。
- 独立岗位版本保存。
- 进入现有编辑器继续修改与导出。

### 7.2 P1 能力

- 岗位定制记录列表与状态筛选。
- 从岗位链接尝试抓取 JD。
- 在编辑器中保留改动来源提示。
- 更多优化重点及个性化偏好。

### 7.3 本期不做

- Dashboard 岗位定制大 Banner。
- Dashboard“最近岗位定制”模块。
- 岗位定制抽屉。
- 事实和数据逐条确认流程。
- 每处改动的接受、拒绝或撤销工作流。
- 在结果页直接编辑简历。
- 在结果页直接下载 PDF。
- 在结果页重复实现模板、字号、颜色、模块和排版工具栏。
- 自动生成打招呼话术、求职信、面试题等附加材料。
- 自动补造公司、学校、职位、日期、学历、证书、奖项、专利或可外部核验的商业事实。
- 以匹配分数承诺 ATS 通过或录用结果。

## 8. 核心流程

```text
Dashboard
  ├─ 侧边栏“岗位定制” → 用户选择基础简历
  └─ 简历卡片“针对岗位优化” → 自动带入当前简历
                         ↓
              填写公司、岗位名称和 JD
                         ↓
                 生成岗位定制版
                         ↓
       AI 分析岗位 → 评估匹配 → 改写内容 → 生成说明
                         ↓
       左侧评分与说明 + 右侧完整简历与 Diff
                         ↓
                   进入编辑器
                         ↓
            修改、排版、预览与导出 PDF
```

用户中途不需要确认事实、选择生成方案或逐条处理 AI 改动。

## 9. 页面与交互规格

### 9.1 Dashboard 默认态

“我的简历”只承担基础简历管理职责。

必须保留：

- 标题“我的简历”。
- 副标题“创建和管理你的基础简历”。
- 顶部“快速生成简历 / 创建空白简历 / 导入已有简历”。
- 最近简历网格及已有操作。
- 侧边栏“岗位定制”入口，可带“新”标识。

必须移除：

- 紫色岗位定制主 Banner。
- “最近岗位定制”模块。
- 任何岗位定制抽屉入口。

点击侧边栏“岗位定制”后进入独立输入页，不预选简历。

### 9.2 Dashboard 简历卡片 Hover 态

普通简历卡片 Hover 后显示两个操作：

1. `针对岗位优化`：进入岗位定制输入页，并预选该简历。
2. `继续编辑`：保持现有行为，进入该基础简历编辑器。

入口只在 Hover/键盘聚焦后增强显示，不改变卡片常态的信息密度。移动端需要在卡片更多菜单中提供等价入口。

### 9.3 岗位定制输入页

页面标题：`为目标岗位优化简历`  
辅助文案：`选择简历和职位描述，一键生成更匹配的投递版本，并清楚展示 AI 改了什么。`

#### 第一步：准备简历

来源模式：

| 模式 | 默认与行为 |
| --- | --- |
| 已有简历 | 默认模式；展示当前选择、更新时间和内容概览；支持更换简历 |
| 文件导入 | 复用现有 PDF/Word 导入能力；解析成功后展示内容概览 |
| 文本粘贴 | 用户粘贴简历文本；解析成功后展示内容概览 |

内容概览至少包含个人信息、求职意向、工作经历、项目经历和核心技能是否存在，以及经历/技能数量。此概览用于发现明显解析缺失，不要求用户逐项确认。

页面必须明确提示：`原简历会被保留，优化结果将保存为新的岗位版本。`

从简历卡片进入时：

- 自动选中对应简历。
- 用户可点击“更换简历”。
- 不跳过岗位信息输入。

无可用简历时：

- 显示“创建空白简历”和“导入已有简历”。
- 完成创建或导入后返回当前岗位定制表单。

#### 第二步：目标岗位信息

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 公司名称 | 否 | 用于记录与结果标题；为空时不阻止生成 |
| 岗位名称 | 是 | 1–100 个字符 |
| 岗位描述 JD | 是 | 建议不少于 100 个字符；过短时提示补充，但允许用户确认后继续 |
| 岗位链接 | 否，P1 | V1 可仅保存链接，不依赖自动抓取 |

JD 输入后应反馈已识别的岗位要求数量。解析失败不清空文本，用户可继续编辑后重试。

#### 优化重点

默认选中：

- 岗位关键词。
- 成果表达。
- 内容精简。

可选：

- 结构优化。

优化重点是可忽略的偏好，不应成为生成前的必答问题。用户不操作时直接使用默认值。

#### 事实保护提示

提交区需要显示：

`AI 只会使用原简历已有事实和数据。薪资、日期、公司、联系方式等基础信息不会被自动修改。`

#### 提交

- 页面只有一个高强调动作：`生成岗位定制版`。
- 未选择简历、岗位名称为空或 JD 为空时按钮不可提交，并在对应区域显示内联错误。
- 提交前显示预期耗时 `20–30 秒`。
- 防止重复点击产生多个相同任务。

### 9.4 AI 生成进度页

页面标题需要包含公司和岗位，例如：`正在生成「字节跳动 · CRM 运营」岗位版简历`。

生成阶段：

1. 准备优化材料：读取简历和岗位信息。
2. 分析岗位匹配：提取岗位要求并寻找简历证据。
3. 生成岗位定制内容：改写允许优化的模块。
4. 生成结果说明：整理改动位置和进一步建议。

交互要求：

- 展示整体进度、每个阶段的等待/进行中/完成状态和有意义的当前任务。
- 完成后自动进入结果页。
- 用户可以离开页面，后台继续任务并自动保存结果。
- 提供“取消生成”；取消前需要防止误触，已取消任务可从原输入重启。
- 系统失败时显示原因和“重新尝试”，重试复用原简历、岗位和优化重点。
- 刷新页面后根据任务状态恢复，不从头创建新任务。

### 9.5 岗位定制结果页

结果页是只读评审页，不是第二个编辑器。

#### 顶部区域

- 面包屑：`岗位定制 / 已生成`。
- 标题：`{姓名}，你的岗位版简历已生成`。
- 副标题：`{岗位名称} · {公司名称} · 基于原简历生成独立岗位版本`。
- 保存状态：`已自动保存`。
- 主按钮：`进入编辑器`。
- 主按钮说明：`可继续修改并导出 PDF`。
- 次级文字操作：`重新定制`。

结果页不再同时显示“编辑简历”和“下载 PDF”两个按钮。导出统一在现有编辑器中完成。

#### 左栏：评分和优化说明

1. `岗位匹配度预估`
   - 优化后分数。
   - 原始分数。
   - 提升分值。
   - 标注“基于 JD 与原简历证据”，不能称为真实 ATS 分数或录用概率。
2. `为什么不是 100 分？`
   - 说明 AI 只使用可验证证据，不会为了高分补写无法确认的经历。
   - 使用“可信比满分更重要”等简洁文案建立信任。
3. `优化结果`
   - 关键词匹配。
   - 能力匹配。
   - 经历相关性。
   - 每项展示得分、提升值、改动数量和一句话总结。
4. `进一步提升建议`
   - 展示 AI 无法安全自动写入、但值得用户补充的内容。
   - 明确标记“未自动修改”。

点击左栏维度或标签时：

- 右侧滚动到第一个对应改动。
- 对应内容短暂强化显示。
- 不出现“接受 / 拒绝”按钮。

#### 右栏：完整简历和 Diff

右栏必须显示完整简历，包括所有未修改模块与内容。

顶部控件：

- `优化后 / 原简历`：在同一预览区域切换完整版本。
- `标记 AI 改动`：默认开启；关闭后隐藏高亮但仍显示优化后简历。
- Diff 图例：`关键词匹配 / 能力匹配 / 经历强化`。

默认状态：

- 展示优化后简历。
- 开启 AI 改动标记。
- 保持完整简历阅读顺序和版式。
- 切换原简历和优化后时尽可能保持相同滚动位置。

#### 高亮详情

点击任一高亮后，在不离开完整简历的前提下显示轻量详情：

- 原文。
- 优化后内容。
- 修改原因。
- 对应的岗位要求或简历证据。
- 改动分类。

详情可使用邻近 Popover 或侧边详情层，但不能遮住大面积简历内容，也不能演变为逐条审批流程。点击外部或按 Esc 可关闭。

#### Diff 语义

| 类别 | 视觉语义 | 内容范围 |
| --- | --- | --- |
| 关键词匹配 | 紫色标签与浅色背景 | 基于 JD 补充或对齐已有能力关键词 |
| 能力匹配 | 绿色标签与浅色背景 | 将已有经历与岗位能力要求建立明确联系 |
| 经历强化 | 橙色标签与浅色背景 | 强化已有成果、数字或职责的表达 |

- 颜色不能成为唯一识别方式，必须配合图例、标签或可访问名称。
- 优化后视图中，高亮新增或替换后的内容；被删除的原文在详情中展示。
- 原简历视图中，高亮被替换或删除的原文；新增内容在详情中展示。
- 每项 Diff 必须保存语义数据，不能只保存页面坐标或颜色。

### 9.6 进入现有编辑器

点击“进入编辑器”后：

- 打开岗位定制副本对应的现有简历编辑器。
- 加载岗位定制后的全部内容和当前模板。
- 支持现有模块编辑、拖拽、AI 润色、排版美化、预览和导出能力。
- 首次进入可显示一次轻提示：`这是岗位定制版本，原简历未被修改。`
- 编辑器内的后续修改只影响岗位版本。
- 返回结果页时仍可复现生成时的原始版本、AI 结果和 Diff；不把用户后续手动修改伪装成 AI 改动。

### 9.7 岗位定制记录（P1）

记录只位于独立“岗位定制”模块，不出现在 Dashboard。

每条记录至少展示：

- 公司与岗位名称。
- 使用的基础简历。
- 优化后匹配分。
- 创建时间。
- 状态：生成中 / 已完成 / 生成失败 / 已取消。
- 操作：查看结果 / 继续编辑 / 重新尝试。

记录入口不能占据输入页的主要视觉层级。列表和删除/保留规则需要补充设计稿后进入 P1 开发。

## 10. AI 内容与事实边界

### 10.1 允许自动优化

- 调整句式、用词、表达顺序和内容精简程度。
- 使用 JD 中的规范术语替换语义一致的宽泛表达。
- 将原简历已有事实与岗位职责建立更清晰的关联。
- 重排或突出更相关的经历和技能。
- 在不改变数值含义的前提下优化成果表达。

### 10.2 禁止自动修改或虚构

- 姓名、头像、电话、邮箱和地址。
- 公司、岗位、学校、专业、学历、证书和项目名称。
- 任职、就读和项目日期。
- 薪资、工作年限和其他基础事实。
- 原简历不存在的技能、工具、职责、项目、业绩和数字。
- 无法从原简历证据支持的因果关系或成果归因。

系统判断证据不足时，必须将内容放入“进一步提升建议”，不能写入岗位版本。

### 10.3 匹配分数规则

- 优化前后必须使用同一评分口径。
- 分数依据为 JD 要求与简历证据的覆盖程度。
- 分数只用于相对比较和解释优化方向。
- 页面必须说明分数不是第三方 ATS 实测，也不代表录用概率。
- 不以追求 100 分为目标；可信和可验证优先。

## 11. 数据与业务规则

### 11.1 核心对象

#### Tailoring Task

- 用户 ID。
- 来源类型：已有简历 / 文件导入 / 文本粘贴。
- 来源基础简历 ID 与生成时版本/内容哈希。
- 公司、岗位名称、JD、岗位链接。
- 优化重点。
- 状态与各阶段进度。
- 创建、开始、完成、失败和取消时间。
- 失败原因与重试来源任务 ID。

#### Tailored Resume

- 独立简历 ID。
- 来源基础简历 ID。
- 对应 Tailoring Task ID。
- 生成时的原始内容快照。
- AI 优化后的内容快照。
- 当前编辑器内容。
- 模板与主题设置。
- 自动保存时间。

#### Optimization Change

- 变更 ID 和所属任务。
- 模块、条目和文本范围的稳定定位信息。
- 原文与优化后内容。
- 分类：关键词匹配 / 能力匹配 / 经历强化。
- 修改原因。
- 对应 JD 要求与来源简历证据。
- 是否仍能定位到当前编辑器内容。

#### Optimization Summary

- 优化前分数、优化后分数和提升值。
- 各维度分数、提升值和改动数量。
- 已完成的优化摘要。
- 未自动修改的进一步提升建议。

### 11.2 保存规则

- 提交后立即创建任务，防止刷新丢失。
- 只有生成结果成功保存后，任务才进入“已完成”。
- 基础简历永不被岗位版本覆盖。
- 文件导入或文本粘贴需要先形成可编辑的基础简历快照，再创建岗位版本。
- 同一次提交的重复请求应复用任务或被幂等拦截。
- 系统失败重试不得重复扣减额度；正式计费规则另行确认。
- 用户后续在编辑器的修改与生成时 AI Diff 分开记录。

## 13. 页面状态与异常处理

### 13.1 输入页

| 状态 | 处理 |
| --- | --- |
| 无基础简历 | 引导创建或导入，完成后返回当前表单 |
| 简历解析中 | 内容概览显示骨架和明确进度，岗位表单可继续填写 |
| 简历解析失败 | 保留文件/文本，说明原因，提供重试或切换来源 |
| JD 为空 | 输入框内联提示，不弹阻断式 Modal |
| JD 过短 | 提示可能影响效果，用户确认后仍可继续 |
| JD 解析失败 | 保留原文，允许编辑和重新解析 |
| 重复提交 | 禁用按钮并复用现有进行中任务 |

### 13.2 生成页

| 状态 | 处理 |
| --- | --- |
| 正常生成 | 显示真实阶段状态，完成后自动跳转 |
| 页面刷新 | 根据 taskId 恢复当前状态 |
| 用户离开 | 后台继续，完成后保存结果 |
| 用户取消 | 状态改为已取消，保留输入供重新开始 |
| 可重试失败 | 显示原因和“重新尝试”，复用输入 |
| 不可重试失败 | 引导更换简历/JD或联系客服 |
| 超时 | 明确提示仍在处理或已失败，不显示永久假进度 |

### 13.3 结果页

| 状态 | 处理 |
| --- | --- |
| 结果加载中 | 左右栏使用与最终结构一致的骨架屏 |
| 部分说明缺失 | 完整简历仍可查看；对应维度显示“暂未生成说明” |
| Diff 定位失效 | 仍显示原文和优化后内容，不执行错误滚动 |
| 岗位版本已删除 | 说明状态并允许基于原任务重新生成 |
| 编辑器保存失败 | 由编辑器现有保存机制处理，不回写基础简历 |

## 14. 非功能要求

### 14.1 性能

- 输入页主要内容可交互时间目标 ≤ 2.5 秒。
- 生成任务创建后的状态反馈 ≤ 1 秒。
- 长简历的 Diff 高亮不得明显阻塞滚动。
- 结果页优先加载首屏，完整内容可渐进渲染，但不得破坏定位。

### 14.2 可访问性

- 所有入口、标签、开关和高亮可使用键盘访问。
- Hover 操作必须有键盘聚焦和移动端等价入口。
- Diff 不能仅依赖颜色表达。
- 文本与背景满足 WCAG AA 对比度。
- 切换版本、定位改动和生成状态需要有屏幕阅读器可识别的状态说明。

### 14.3 隐私与安全

- 简历和 JD 按用户隔离，不在不同用户间复用。
- 日志不得记录完整联系方式、简历正文或 JD 原文。
- 文件导入沿用现有类型、大小、病毒和解析安全限制。
- 向模型发送的数据应遵循最小必要原则。
- 删除任务时需要明确其对岗位版本和 Diff 的影响。

### 14.4 响应式

- 桌面端结果页使用左侧说明、右侧完整简历的双栏结构。
- 小屏端改为先展示评分摘要，再展示完整简历；说明区可折叠。
- 小屏端保持原简历/优化后切换、Diff 开关和高亮详情能力。

## 16. 验收标准

### 16.1 Dashboard

- [ ] 页面副标题为“创建和管理你的基础简历”。
- [ ] 顶部三个基础简历快捷入口均保留。
- [ ] 不存在岗位定制大 Banner。
- [ ] 不存在“最近岗位定制”模块。

- [ ] 侧边栏和卡片入口均进入带应用导航的独立页面。
- [ ] 从简历卡片进入时正确预选当前简历。

### 16.2 输入与生成

- [ ] 用户可选择或更换已有简历，也可导入文件或粘贴文本。
- [ ] 内容概览能提示主要模块是否成功解析。

- [ ] 默认优化重点已设置，用户无需额外配置。
- [ ] 点击一次“生成岗位定制版”即可开始。
- [ ] 生成过程中没有事实确认或逐条修改确认。
- [ ] 生成失败、刷新或重试后原输入不会丢失。
- [ ] 完成后自动进入结果页。

### 16.3 结果页

- [ ] 左栏同时展示原始分、优化后分和提升值。
- [ ] 左栏明确区分已自动完成的优化与未自动修改建议。
- [ ] 右栏展示所有简历模块和完整内容。
- [ ] 默认展示优化后简历并开启 AI 改动标记。
- [ ] 用户可关闭高亮而继续阅读完整优化后简历。
- [ ] 用户可在同一预览区域切换到完整原简历。
- [ ] 点击左栏维度能定位到右栏对应改动。
- [ ] 点击高亮能看到原文、优化后、修改原因和证据。
- [ ] Diff 除颜色外还有文字图例或可访问名称。
- [ ] 不存在逐条接受、拒绝或撤销操作。
- [ ] 页面只有“进入编辑器”一个主要后续 CTA。
- [ ] 结果页没有直接下载 PDF 按钮。

### 16.4 编辑器与数据

- [ ] 点击 CTA 进入项目现有真实简历编辑器。
- [ ] 编辑器加载岗位定制后的完整内容和模板。
- [ ] 用户能在编辑器内完成修改、排版、预览和导出。
- [ ] 基础简历不会被 AI 结果或后续编辑覆盖。
- [ ] 原始快照、AI 结果和每一处 Diff 都可追溯。
- [ ] 用户后续手动修改不会被错误标记为 AI 改动。
