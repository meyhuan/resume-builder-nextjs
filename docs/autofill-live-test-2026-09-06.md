# 网申插件 0.4.0 真实浏览器测试

日期：2026-09-06（Asia/Shanghai）。分支：`codex/application-autofill`。

## 范围与方法

用户授权使用现有网申资料测试腾讯、淘天，禁止保存、提交；仅记录和定位问题。
通过 Computer Use 在当前 Chrome 点击插件并核对页面；通过浏览器只读 DOM 检查定位结构差异，通过本地服务日志核对接口响应。
Chrome 扩展管理页实测版本为 0.4.0，侧栏显示已连接；本地 Next 服务地址 localhost:3000。
没有修改产品代码，没有点击招聘网站保存、提交简历、协议或插件的“我已完成投递”。

注意：插件当前逻辑会自动创建或复用智简简历内的“待投递”记录；本轮确实触发了该行为。这不代表向招聘公司提交了申请。

## 已定位问题

### P1：淘天区块识别的层级上限不足

- `extension/lib/page-scanner.ts` 中 `locateSection` 只检查 depth < 12 的祖先。
- 真实工作经历的职务输入到 `.uxcore-card.form-card.social-work-experience-card` 在 depth 14；描述在 depth 13；日期在 depth 15（父元素从 0 计）。
- 标题 `.uxcore-card-title-text` 确实存在，但超出了扫描范围。因此读到标签后缺少经历归属，作用域内“职务/职务描述/开始日期”等别名无法生效，自动新增也没有获得区块。
- 实际重复记录为 `.field-group-row`，祖先为 `.uxcore-form-field-group-inner-wrap`。是否还存在独立的重复行识别问题，需要修复标题定位后再回归，不能认为仅调大深度即可完全解决。
- 建议：优先从可识别表单/卡片容器建立区块，再关联字段；补真实深层嵌套结构回归样例，而非仅增加公司域名判断。

### P1：腾讯工作结束日期选择器不符

- `extension/lib/site-adapters.ts` 使用 `.create-empirical .end-time-module`，真实 DOM 匹配数为 0。
- 页面第 2～4 条工作经历实际使用 `.resume-module-right.end-time`。
- 三条结束年月均保持“年/月”占位符，未进入相应失败或缺资料明细。
- 教育开始/结束年月已显示具体日期，与工作结束日期问题不同。
- 建议：修正结构匹配，同时增加“可见但未扫描到的复合日期控件”覆盖检查。

### P2：淘天学历成功选择被误报失败

- 页面已显示“本科”，但首次插件失败项为“学历”。
- 真实已选值元素为 `.kuma-select2-selection-selected-value`，当前 `fill-executor.ts` 的已选值选择器不包含它。
- 回退读取 `.kuma-select2-selection__rendered.textContent` 会包含隐藏占位符，实际得到“请选择本科”，无法与目标值严格相等。
- `aria-expanded=false` 在内部 `[role=combobox]`，不是插件标记的外层 `.kuma-select2`。
- 建议：区分外层、交互主体、已选值节点，排除隐藏占位符；复验成功信号而不是搜索字符串。

### P2：淘天日期目前明确缺少通用驱动

- 工作、项目、教育日期输入均为 readonly，外层为 Kuma 日历控件。
- 即使修复区块识别，当前通用执行器仍会将这类 readonly 字段归为 unsupported；需要额外的日期控件交互实现。

### P2：结果提示容易误导

- 淘天显示“20 个通过标签或上下文识别”，但很多字段并没有完成资料映射。该指标实际上更接近“获得标签的控件数”。
- 侧栏失败、缺资料展示使用去重后提示条目数，不能与检测控件总数直接相加核对。
- 从腾讯切换至淘天后，在再次点击填写前，侧栏仍保留腾讯填写结果和待投递记录，容易误认为是当前页结果。
- 建议：区分检测、映射、执行、复验四阶段，并按当前标签页隔离结果。

## 埋点与接口

- 本轮服务日志出现多次 `GET /next-api/extension/profile 200`。
- `POST /next-api/extension/analytics` 多次返回 204，证明请求到达 Next 接收接口。
- `POST /next-api/extension/applications` 返回 200，对应插件自动留存待投递记录。
- 尚未查询 Java 埋点存储/分析后台；204 不能单独证明最终入库。`src/lib/server-analytics.ts` 会捕获转发异常，因此必须补端到端入库验证。

## 结论

腾讯经历自动新增已可用，但工作结束日期有明确遗漏；淘天通用识别尚不能作为完整简历填写上线验收通过。
新增自动化测试没有覆盖真实深层嵌套、隐藏占位文本和腾讯实际结束日期类名，需要补这三类回归。
本轮仅测试及定位，未实施修复；未保存或提交招聘网站简历，未确认已投递。

## 后续修复：0.4.1（与上面的 0.4.0 实测区分）

用户继续后，在同一独立工作树实施以下修复：

- 扫描时一次建立标题祖先索引，取消 12 层限制；遇到混合区块仍停止归属推断。
- 增加 UXCore 通用 `.field-group-row` 记录识别，新增行不依赖分隔线等可变装饰类；不是新增淘天域名适配器。
- 腾讯工作结束日期兼容 `.end-time`，并通过已配置的经历行计算资料索引，防止首条在职经历缺少结束日期时造成错位。
- UXCore 单选读取可见已选值，忽略隐藏占位符；检查内部 combobox 的收起状态，避免学历成功后误报失败。
- 侧栏缺资料和未填写数字使用控件数，提示标签识别不等于已映射/已填写。
- 完成事件的引擎版本标为 `openjob-context-v2`，插件版本 `0.4.1`，方便区分后续效果数据。
