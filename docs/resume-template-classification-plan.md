# 简历模板分类与制作排期（整合草案）

更新：2026-09-26。状态：供用户评审的分类规划，尚未实施分类筛选，也不代表批准任何下一款模板。

## 1. 已有规划与本次边界

此前已经有两份规划，不是从零开始：

1. 仓库 [50 个简历模板规划](50-resume-template-roadmap.md)：8 个制作分类、50 个候选概念及批次。它是扩展构想，不是 50 款已批准设计，也不是实际发布清单。
2. 历史任务「评估并优化简历模板」（`01a0ae1d-0c7f-75e3-a276-3ba60b7e7c2e`）中的《简历模板分类与模板中心 MVP》：求职场景入口、内容结构及版式/语言等筛选、统一元数据、现有模板归类与验收。

本次保留旧方案的主体，明确两者职责，并修正已失效的事实和未经验证的能力标签。原方案中的数量配额、推荐排序、页数与 ATS 标签均不能当作用户需求数据或已验收能力。

- **制作分类**：用于盘点、补缺和选参考稿；每款只有一个主分类。
- **用户筛选**：用于找到适合自己的已有模板；同一模板可以出现在多个场景。
- **发布状态**：单独记录；归类正确、已经注册、已有缩略图都不等于可发布。

后续规划优先维护本文；覆盖与验收进度维护在 [覆盖路线图](resume-template-roadmap.md)。旧 50 款文档保留作历史候选库，不再自动按数量排产。

## 2. 制作分类：沿用原有 8 类

以下是基于当前注册描述的**初始归类建议**，不是已逐款完成视觉或发布验收。计数为编辑器可选模板的互斥主分类总数，不是公开目录数量。

| 主分类 | 判定依据 | 现有模板 ID / 名称 | 数量 | 下一步 |
| --- | --- | --- | ---: | --- |
| 通用高级型 | 通用经历/项目阅读；不依赖特定职业装饰 | `simple` 简约、`warm` 双栏、`timeline` 时间轴、`xinghe` 星河、`lanjiao` 蓝角、`lanmu` 蓝幕、`lanying` 蓝营、`qiance` 浅策 | 8 | 现有覆盖较多；整理推荐入口，不优先新增同构单栏 |
| 校招应届型 | 教育、实习、校园与项目内容适配；少经历也可读 | `qingsui` 青穗、`lanzhe` 蓝折、`lanzix` 蓝紫、`shanglan` 商蓝、`qingyun` 青云、`qingning` 青柠 | 6 | 复用校招/实习双场景；重点复核稀疏内容，不按配色追加 |
| 技术工程型 | 技能与项目成果的阅读层级清楚 | `lifeng` 砺锋、`mashang` 码上 | 2 | 先检查项目阅读与公开入口；不把终端装饰作为分类依据 |
| 紧凑专业型 | 信息密度较高、节省空间，仍保持可读性 | `yiyetong` 一页通、`dense` 密排、`jijian` 极简黑 | 3 | 验证字体与分页；不承诺任意内容都能一页 |
| 创意表达型 | 内容/设计岗位的视觉表达与项目呈现 | `ziji` 紫记、`zhumo` 朱墨 | 2 | 有风格覆盖；评估简历与已有图片作品集附录的衔接 |
| 正式稳重型 | 克制排版、完整履历，适合偏正式材料 | `elegant` 典雅、`tablegrid` 表格、`hengjian` 衡简、`lanfa` 蓝法、`jinhang` 金行、`heijiao` 黑教、`xingtan` 杏坛 | 7 | 教师是辅助场景；不能把教师风格当作完整科研 CV |
| 资深管理型 | 长履历、关键成果与多页连续性 | `yuanshan` 远山 | 1 | 已有专项修复记录；先验收真实长履历，再决定是否扩款 |
| 特色差异型（当前为英文/国际化） | 英文排版、日期、长词与无头像场景 | `moxu` 墨序 | 1 | 墨序已落地；双语仍需单独验证，不能因双语标题就宣称支持 |

合计 30 款。隐藏的 `lanxin` 蓝芯单列为历史兼容模板，不纳入上述可选数量，不删除其旧简历加载能力。已移除的“直投”不纳入清单。

旧方案计划配额分别为 10/8/7/7/6/6/4/2；本次不沿用配额作为生产目标。例如正式类已有 7 款，不应为了旧计划再造 6 款。

Skill 中“通用职场、正式商务、技术投递、英文商务”等是对应类别的工作用语，不是另一套已批准分类。“教师科研”暂作为专项需求：教师已有风格覆盖，科研长 CV 待验证；如确有独立结构需求，再提议新增制作分类。当前不擅自扩为第 9 类。

## 3. 用户入口：沿用场景优先，允许交叉

保留旧 MVP 方案的场景，不将制作分类原样复制成互斥导航。

| 场景键 | 用户文案 | 初始匹配依据 / 候选代表 |
| --- | --- | --- |
| `general` | 通用简历 | 通用高级型、紧凑专业型；兜底入口，不等同于某个职业 |
| `campus` | 应届校招 | 校招应届型；教育、校园、项目样例 |
| `internship` | 实习求职 | 青穗、蓝折、蓝紫、商蓝、青柠等；少经历与实习样例 |
| `professional` | 社会招聘 | 通用、正式、紧凑等已有模板；工作/成果样例 |
| `executive` | 资深管理 | 远山；需长履历和多页证据 |
| `english` | 英文求职 | 墨序；其他模板只有英文专项验收后加入 |
| `academic` | 学术科研 | 保留需求，但暂不推荐仅有教师风格的模板；无合格项时不展示可选分类 |
| `technical` | 技术岗位 | 砺锋、码上；可交叉推荐经验证的通用项目型模板 |
| `creative` | 设计与内容 | 紫记、朱墨；入口辅助说明“可附作品集”，不宣称模板本体都是作品画廊 |
| `traditional` | 正式投递 | 正式稳重型；不宣称满足所有单位的指定格式 |

与旧 MVP 的差异：`creative` 文案由“设计作品集”改为“设计与内容”，避免把图片附录能力误当成专属简历版式；`traditional` 由“传统行业”改为“正式投递”，避免按行业刻板分配样式。以上均为本次建议，尚待评审。

“推荐模板”和“全部模板”是列表视图，不是分类枚举。推荐使用人工维护的已验收名单，不声称智能匹配。场景数不是各主分类数量简单相加，交叉模板按 ID 去重；仅统计该页面有权展示的模板。

界面采用场景选择 + 可展开筛选，不把所有入口与所有筛选同时堆在窄侧栏。桌面编辑器、移动端与公开模板页共享语义；呈现形式可适配空间。无结果提供清除条件，不偷偷放宽条件或改变用户简历。

## 4. 辅助维度及证据规则

旧 MVP 方案保留结构化筛选，但调整混淆项：

- 内容重点：经历、项目、业绩、技能、学术成果、作品。它是推荐用途，不会自动调换已保存模块或注入示例内容。
- 版式：单栏、双栏、表格。时间轴和侧栏另作结构特征，可与单双栏共存；作品集附录不是简历主版式。
- 密度：舒展、标准、紧凑。密度判断依据同一套样例渲染，不根据名称猜测。
- 页数：区分“一页倾向”与“多页已验证”；实际页数由内容与主题决定。标注验证样例/报告，不设保证一页的承诺。
- 语言：中文、英文、双语。只展示实际验证过的语言；能输入英文或有英文小标题不等于完成英文排版验收。
- 风格：极简、商务、正式、清爽、创意、经典；黑白/彩色可作为外观标签。颜色不是制作主分类。
- 头像：可选、无头像设计、头像布局已验证等描述须基于真实行为；不只用一个 `hasAvatar` 布尔值混淆参考样图与编辑能力。
- ATS：从内容分类移到验证记录。可记录文本可提取、阅读顺序检查；未实测第三方系统，不展示“ATS 认证/完全兼容”。

岗位预设继续独立负责内容提示、推荐模块、技能词和 AI 写作问题。用户选择模板或筛选场景时，不自动改岗位、模块顺序、真实经历或主题。

## 5. 现状与缺口：先分辨入口、结构和验收

本次本地只读核对结果：

- `src/templates/template-loader.ts`：31 个注册项，隐藏蓝芯后 30 个可选。
- `src/lib/templates/template-catalog.ts`：27 个定义项，过滤蓝芯后 26 个公开目录条目。
- 青云、码上、朱墨、杏坛在编辑器注册但不在公开目录；这属于展示策略差异，不等于模板不存在，也不自动授权公开这 4 款。
- `src/ui/right-sidebar.tsx` 仍显示 `tags?.[0]`；注册类型尚无结构化 taxonomy。历史 MVP 计划没有在这些入口落实。
- 当前已有 `ResumePortfolio` 图片数据、上传排序说明编辑组件，以及编辑器/移动预览/打印页的 `PortfolioAppendix`。因此“作品集完全缺能力”的旧判断不准确；仍需真实上传、保存重开、导出与简历衔接的专项验收。
- `src/entities/module/module-config.ts` 有项目、教育、奖项和自定义模块，未定义专用论文/引用模块。可先验证自定义富文本是否满足科研需求；需要结构化作者、期刊、DOI、排序时，应单独确认产品范围，不能在模板中虚构字段。

这里的代码存在性检查不是本轮功能测试；没有重新认证所有模板的发布状态。

## 6. 下一阶段排期建议

优先级基于当前重复覆盖、已有能力和实施依赖，不是用户使用率排名。

| 顺序 | 工作包 | 完成条件 | 是否新增模板 |
| --- | --- | --- | --- |
| P0 | 统一分类与展示策略 | 30 款归类核对；4 款目录差异明确原因；所有入口使用同一元数据与可见性规则 | 否 |
| P0 | 分类筛选 MVP | 桌面/移动/公开目录语义一致；交叉筛选、计数、清除条件、切换保真均通过 | 否 |
| P1 | 创意表达 / 作品展示专项 | 验证已有图片附录与简历衔接；只有发现现有样式无法满足的结构需求才选参考款 | 视专项结论 |
| P1 | 学术科研需求验证 | 用真实结构样例明确富文本是否足够；长 CV、成果列表和分页验收 | 需先明确能力范围 |
| P2 | 资深管理、技术工程补缺 | 先复核远山/砺锋/码上已有能力；有明确差异再选款 | 非默认新增 |
| 暂缓 | 通用、校招、正式、紧凑同构扩款 | 有新的真实需求、参考结构差异或使用数据才重排 | 暂不新增 |

**下一步建议先落实 P0 的分类元数据与筛选，而不是继续随机生产下一款。** 若用户希望先扩模板，首个研究方向建议是创意表达与已有作品附录的衔接；这不是已确认的下一款分类，更不代表自动批准任何 Canva 候选。

## 7. 实现交接与验收（待实施）

### 单一元数据源

建议新增无 React/组件导入的共享元数据模块，包含 ID、名称、缩略图、制作主分类、多场景、筛选字段、独立的编辑器/公开页可见性与验收证据。`template-loader.ts` 负责把元数据与 lazy 组件映射组合，`template-catalog.ts` 从纯元数据派生公开目录。

这修正旧方案“公开目录直接依赖模板 loader”的建议，避免公开/服务端目录被迫依赖组件加载注册表。保留模板 ID、旧数据读取和暂用 `tags` 的兼容性；不改数据库里的用户内容。

公开数与编辑器数不要求强行相等；要求差异显式、有理由、可测试。未确认 4 款展示策略前，迁移应保留当前可见性。

### 交付顺序

1. 审核本文分类和展示策略；补齐逐款字段的证据，不把初始归类当成验收结果。
2. 提取纯元数据与组件映射，保持 ID/默认排序/旧模板可加载。
3. 实现纯筛选、稳定排序、计数函数。同一维度多选 OR，不同维度 AND；未知能力不匹配“已验证”筛选；无条件返回当前视图的稳定名单。
4. 接入 `src/ui/right-sidebar.tsx`、`/templates` 及岗位模板页、首页模板入口、移动首页/预览选择器；开发场景页继续复用相同数据。
5. 卡片显示用户可理解的场景与结构，替换仅 `tags[0]` 的方式；保留 `data-template-id`、正在使用状态与切换逻辑。
6. 场景与筛选状态仅影响列表，不写用户简历；刷新默认推荐视图；不符合当前筛选的正在使用模板仍可在“正在使用”区域定位。

### 验收要求

- 数据：31 个注册 ID 可解析、30 个可选无遗漏，隐藏模板不泄露，4 个目录差异显式，主分类唯一、场景可多选、缩略图存在。
- 筛选：单条件、跨条件交集、同维度并集、去重计数、稳定排序、无结果、清除与未知能力处理。
- 交互：编辑器/移动/公开目录规则一致；筛选不修改简历；切换不丢内容、主题、模块顺序或保存状态；窄屏无意外溢出。
- 回归：先检查仓库现有测试配置再确定新增测试命令；执行 TypeScript、相关 ESLint、生产构建与 `git diff --check`。涉及模板渲染/切换变更时按 [固定模板工作流](template-creation-workflow.md) 执行受影响模板 QA，并记录实际报告和跳过项。
- 发布：分类筛选上线验收与模板款式验收分别记录；通过其中一项不代表另一项自动通过。

## 8. 每次制作必须填写的选型单

制作主分类（只能一个） → 用户场景（可多个） → 现有模板不能满足什么 → 参考 URL/ID/文件 → 用户确认记录 → 高还原/改编/原创模式 → 所需现有模块与能力缺口 → QA 证据 → 发布判断。

“继续下一款”只从已确认分类与参考稿的选型单推进。没有完整选型单时停在选型，不继承已撤销“直投”的定位，不把本规划中的建议优先级当作用户批准。
