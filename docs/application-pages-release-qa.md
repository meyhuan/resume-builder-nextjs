# 网申资料与投递管理发布前验收

范围：`/dashboard/application-profile`、`/dashboard/applications`；工作分支 `codex/application-autofill`，不修改主干，不部署正式站。

## 本轮改动

- 两个页面的请求统一使用15秒超时、中文错误提示及401重新登录提醒。写请求超时只说明结果未确认，不声称服务器一定没有写入。
- 资料读取失败显示独立错误与重试入口，不允许把未加载的空白表单保存覆盖原资料；插件授权列表失败单独提示。
- 资料未保存时阻止同步，保存期间的新编辑保留未保存标记；同步期间的新编辑不被响应覆盖。
- 资料站内链接跳转、投递抽屉关闭时提示未保存内容；浏览器刷新/关闭保留离开提醒。
- 投递更新改为服务器确认后更新列表；创建、更新、删除失败保留原状态与输入，解除忙碌状态以便重试，防止重复请求。
- 创建重用记录时按ID去重，创建后清除旧筛选；提醒和分类筛选支持重复点击取消。

## 验证方法与边界

`node --env-file=.env scripts/test-application-pages-browser.mjs <明确的测试数据库主机>`

使用隔离Puppeteer Chromium和唯一 `dashboard-browser-qa-` 合成账号，测试脚本为该账号设置当前项目的本地会话Cookie；**不等同于真实扫码登录验收**。辅助Java/VIP接口使用桩并阻止外站网络，资料、简历同步、投递及插件资料读取使用真实Next接口和明确指定的测试数据库。

只故意中断特定读取/保存/创建/更新/删除请求以模拟断网，并注入一次401检查保留编辑；不将故障注入结果当作真实授权过期验证。测试结束清理本轮合成账号及其简历、资料、授权和投递记录。

数据库存在已观察到的间歇连接失败及首次读取超过15秒问题。测试可以通过界面显式重试读取，日志标注WARN；不能将重试后的业务通过解释为数据库稳定。

补充只读复测：3次独立Prisma连接执行 `SELECT 1` 均成功，耗时5186/5226/5199ms（包含客户端初始化及建连，不是业务接口耗时）。说明当前本机可连接，但不足以证明部署环境的延迟、稳定性或真实登录流程。
