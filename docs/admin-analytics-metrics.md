# 管理后台统计口径

本文描述当前代码口径；文末记录限定时间窗口的线上快照核对，不代表全历史或埋点完整性认证。埋点缺失、拦截、设备切换和账号关联不足都会影响行为数据；金额以订单表为准，不是支付渠道结算或财务净收入。

## 时间和筛选

- 主统计选择最近 N 天时，以后端服务器本地时区的自然日计算，包含今天；区间为 N 天前的零点（含）至明天零点（不含）。今日访问只统计今天。事件时间是服务端记录的时间。
- 模板链路按北京时间、插件填写报表按服务端当前时刻向前 N×24 小时计算，不能与自然日数据直接当作相同时间范围比较；模板使用北京时间查询记录，当后端系统时区不同时需核对时间偏移。
- 切换筛选后需要刷新；刷新前保留上次结果并显示提示。客户端类型筛选只作用于生命周期链路，历史数据可能没有客户端类型。
- Web 与 H5 支付筛选对应同一类 Web 订单；小程序对应小程序订单，服务端筛选不匹配订单。事件平台和订单来源不是同一个字段。

## 概览及行为

- **今日访问 UV（估算）**：客户端 `page_view` 的去重身份数。当天其他客户端事件可将匿名 ID 或会话 ID 关联到唯一账号；当两个标识各自关联到不同账号时保留匿名身份，无法唯一关联的标识不会单独指向某个账号，缺少所有身份的事件不计。跨设备未能关联、共享设备和缺失埋点仍可能造成偏差。
- **事件总数和事件分布**：在范围和平台内的事件条数；各事件的身份数独立去重，匿名和账号可能重复。支付、导出、新建卡片只展示事件次数，不表示按顺序发生的用户转化。
- **生命周期**：仅在所选范围内按时间先后完成前序步骤的身份计入顺序人数；独立人数是单步身份数。范围之前已登录、创建的老用户及缺失埋点可能不进入完整链路。Web 的 H5 支付按账号关联；PC/移动拆分依赖新版客户端属性。生命周期支付事件人数与订单支付人数口径不同。
- **模板统计**：以模板埋点记录的曝光、主动选择、保存、导出链路为准；指标具体限制见页面说明。历史数据不会自动回填为完整链路。

## 渠道与订单

- 渠道的访问、登录和导出分别按对应事件的账号或匿名 ID 独立去重，同一人登录前后或出现在多个渠道可能重复，不能相除计算转化率。
- 接口不再返回将独立事件相除得到的渠道转化率或事件分布的 `conversionFromFirst`。如果其他系统使用这些字段，更新前需同步调整；前端与后端应配套发布。
- 渠道付费使用当前状态为已支付的真实订单，按支付时间筛选；支付时间缺失时依次使用更新时间、创建时间。对每笔订单，在付款前 30 天内寻找同账号、同订单端的最近一条带来源的指定客户端事件；无法匹配或来源不可用时计入“无法归因”。来源来自客户端已保存的归因信息，不一定等于最后一次真实推广触点。人数按渠道内账号去重，同一人可能在多个渠道出现，渠道人数不可直接相加。
- 现有小程序客户端将普通事件的来源固定设为 `wechat`，并未识别具体推广渠道。此类行为显示为“小程序（来源未细分）”，不能用于订单的推广来源归因；没有其他有效来源的订单计入“无法归因”。
- 用户自报来源使用选择或跳过事件，页面“主动选择次数”是事件数，“回答身份数”按账号或匿名 ID 独立去重；不是订单归因。
- 已支付订单数、金额和会员结构：筛选窗口内支付、当前状态为已支付的订单；退款等非已支付状态不计。金额为订单金额之和，客单价为金额除以订单数。支付时间缺失时依次回退到更新时间、创建时间，因此历史订单可能出现时间偏差。
- 订单创建后支付比例：按创建时间选择订单，以当前状态为已支付的订单数除以创建订单数；可包含跨期支付，退款等非已支付状态不计，尚未完成的订单会影响近期比例。

## 错误和插件

- 错误排行从范围内最近最多 500 条错误事件聚合，最多显示 20 组；超出 500 条时页面提示样本量和总数，不能视为全量排行。
- 浏览器插件尚未接入主生命周期链路，应使用“插件填写效果”专用报表；该报表基于已入库的填写结果，超过采样上限时页面提示。字段写入成功不等于招聘网站已保存或投递成功。

本次优化：渠道将多次 COUNT DISTINCT 合为按身份预聚合；生命周期每个身份仅计算一次有序链路，去除无用复制和排序；模板由 Java 一次排序并保留接收时间及 ID 的稳定顺序；页面每次刷新最多并发 3 个请求。

最终 SQL 线上复测截止 14:43:17：今日平台查询 0.474→0.127 秒、渠道 0.050→0.037 秒，结果校验和一致；7 天渠道新查询 0.877 秒，旧查询超过 6 秒限时。早一轮原型测试 7 天渠道为 1.783→0.923 秒且校验和一致。耗时受缓存及线上负载影响，不是稳定性能保证。最终 7 天平台查询及 30 天平台/渠道查询仍超过 6 秒限时；不应声称长周期性能问题已解决。后续应在隔离副本验证覆盖索引或预聚合，包括写入成本、存储及去重口径，再安排独立发布。

复现工具位于后端仓库：`scripts/analytics-readonly-audit.py`（限时只读提取/基准）、`scripts/analytics-audit-oracle.py`（独立计算）、`AnalyticsSnapshotReplayTest`（真实服务回放）。脱敏快照及详细结果保存在后端忽略目录 `target/analytics-audit/`，不提交事件明细。SQL 集成测试 `AnalyticsAggregationSqlTest`、`AnalyticsOrderSqlTest` 仅在显式配置的测试数据库连接内建立临时表。
