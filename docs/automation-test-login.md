# 网页测试账号登录

用户已为网页测试提供专用账号。进行已获授权的 PC 网页检查时，优先复用已有登录会话；需要登录时使用以下入口，不必默认要求用户微信扫码。

## 登录入口与凭据

- 线上入口：`https://aijianli.cn/login?automation=1`。
- 本地入口：当前本地服务地址的 `/login?automation=1`。
- 本地使用 `localhost`、`127.0.0.1` 或 `[::1]` 访问时，普通 `/login` 和登录弹窗默认显示测试账号密码表单，并展示凭据来源说明，不需要手动添加参数。`?automation=0` 可切换为微信登录，页面仍保留测试登录按钮。生产域名继续通过显式参数启用测试入口。
- 客户端登录需要 `AUTOMATION_LOGIN_USERNAME`、`AUTOMATION_LOGIN_PASSWORD`。优先使用已注入的环境变量，否则从 `~/.codex/secrets/aijianli-automation.env` 读取。本机绝对路径为 `C:/Users/62765/.codex/secrets/aijianli-automation.env`。
- 凭据文件不在 Git 仓库内，不随提交、部署包或 worktree 复制。其他电脑需单独配置凭据，文档不保存账号密码的值。
- 将凭据直接传给登录表单或测试程序，不输出文件内容，不把密码硬编码进脚本，也不截取已填入凭据的表单。

## 使用方式

1. 检查当前会话是否已登录；已登录则继续原测试。
2. 如需登录，打开上述入口，使用本地凭据完成表单登录。
3. 确认已进入登录后的页面，再继续用户授权的测试范围。专用账号登录不额外授权修改已有简历、消耗额度或执行发布。

程序化测试可在同一站点会话内向 `/next-api/auth/automation-login` 发送 POST JSON，字段为 `username`、`password`，并保留成功响应建立的 Cookie。需要浏览器客户端状态时，可参考 `scripts/test-unified-ai-live-browser.mjs` 中的登录初始化部分；该脚本的完整运行还会执行 AI 请求和数据写入，**不能仅为登录而直接运行整个脚本**。不要直接用 `AUTOMATION_LOGIN_AUTH_UID` 伪造登录 Cookie。

## 配置和失败处理

`AUTOMATION_LOGIN_ENABLED` 和 `AUTOMATION_LOGIN_AUTH_UID` 是服务端配置，URL 中的 `automation=1` 只选择登录入口，不会启用服务端能力。本地服务需要单独配置对应环境变量；不要为登录测试自动改动生产配置。

- 404：可能未启用自动化登录；核对当前目标环境和服务端配置。
- 401：凭据被拒绝；停止重复尝试，检查凭据来源。
- 403：检查请求是否同源。
- 429：触发尝试次数限制，按响应提示等待，不绕过限制。
- 503：服务端配置缺失或测试账号未初始化。

如无法使用此入口，说明具体原因后再向用户索取缺失信息。文档适用于 PC 网页及 H5 登录，不替代微信开发者工具自身的扫码登录。
