# 0.4.4 日期补全确认验收（2026-09-06）

## 实现范围

- 默认不补造日期；已识别的日精度控件遇到年月资料时显示中文确认。
- 用户可仅本次使用当月1日、主动记住当前网站的选择，或保持空白手动填写。
- 本机按 origin 存储偏好，可重置为询问，不改变原资料，不跨网站复用。
- 原生日期旧分支不再无条件追加01；确认后的值做日期合法性校验、补零与回读验证。
- 只在已确认写入成功时统计补日数量；已有值、月精度控件和“至今”不补日。
- 新增 fill 结果属性 dateCompletionPolicy、dateCompletionAppliedCount 及服务端允许字段；无日期内容上传。

## Computer 实测与间歇性连接问题

1. 通过 Chrome 扩展管理页重新加载现有插件，版本从0.4.3变为0.4.4。没有安装新插件或变更权限。
2. 切到已有淘天招聘表单，打开侧栏，点击默认“一键填写此页面”。
3. 首次显示 Failed to fetch：本地3000端口没有服务。启动当前 worktree 的 `pnpm run dev`，服务就绪。
4. 重试后 `/next-api/extension/profile` 与 `/next-api/extension/analytics` 返回500。Prisma日志确认无法连接测试数据库5432端口，尚未读取到资料，因此没有进入扫描/新增行/字段写入流程。
5. 独立只读 TCP 检查显示5432端口可建立连接；因此不能简单归因为端口被封，应用层数据库连接仍需排查。
6. 再次重试，资料接口200（约10.7秒），投递草稿接口200；侧栏实际显示“17个日期只有年月”的确认卡片。“在此网站记住选择”默认未勾选。
7. 点击“保持空白，手动填写”，确认卡片消失，结果显示检测51个控件、已填0、原本有值29、资料待补充2、暂未填写20。工作经历仍为4条，新增0条。当前可见的开始/结束日期仍空白，无日历浮层残留。

本轮未点击网站保存、提交、协议或插件“我已完成投递”。没有点击“使用当月1日”，没有修改用户真实日期或持久化日期偏好。插件成功读取后仍调用现有本地投递草稿接口，不能表述为零写入。没有修改数据库配置或结构。

## 结论与待验收

实现、自动化测试与构建通过；通过真实淘天页面验证了默认确认卡片与保留空白分支。不能声称真实淘天日历补日成功。

- 由用户确认是否允许将真实资料的年月临时补为1日进行不保存测试；本轮没有默认推定这种授权。
