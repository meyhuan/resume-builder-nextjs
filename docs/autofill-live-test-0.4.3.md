# 0.4.3 修复与真实浏览器复测

日期：2026-09-06。分支：`codex/application-autofill`，独立 worktree；未修改 main。

## 范围与方法

- 使用 Computer Use 操作用户现有 Chrome，重新加载已安装的本地插件，并在扩展管理页确认 0.4.3。
- 腾讯与淘天均沿用已有网申资料和未提交表单，不刷新、不清空已有经历。实际点击插件“一键填写”，辅以只读 DOM 核验。
- 未点击招聘网站保存、提交、协议或“我已完成投递”。插件会创建/复用智简简历待投递记录，不能称为完全无写入测试。
- 为定位城市问题，只读打开本地网申资料页，确认目标城市；在淘天手动测试了一次城市搜索。该控件失焦时自动选择了搜索结果，随后撤回本轮手动产生的选择，恢复空值，再独立运行插件。最终城市成功不是把手动选择算成插件结果。

## 修复内容

1. 腾讯开始年月只选择左侧独立控件，不再吞掉同一大容器中的结束年月。年月选项点击后等待渲染并读回；保留已有完整日期，部分日期冲突时不覆盖。
2. 日历向编辑框写入后等待受控组件渲染再确认；通过弹层 Escape/页面空白 mousedown 关闭弹层，并核验是否关闭。未关闭时停止继续打开日期/级联弹层。
3. 淘天日历是日精度控件。资料只有年月时不补造每月 1 日，而是显示“资料只有年月，此处需要具体日期，请手动选择”。同一类日历后续年月字段不重复打开。
4. 扫描时排除日历、下拉菜单、级联弹层里的内部编辑框和搜索控件，修复打开弹层时统计虚增（中途实测曾从 51 增到 102）。
5. 投递记录按 tabId + 完整 URL 保存在 session；切换标签/导航立即清空侧栏旧结果，旧异步响应不能覆盖新页面，确认投递也核对当前页面关联。增加同标签填写互斥和导航阶段校验。
6. 补充 education[].description 候选，描述 textarea 不再退回学校/公司等名称字段。已有错误值不自动覆盖。
7. 搜索下拉框先关闭旧弹层，搜索后最多等待 2 秒以覆盖远程选项延迟；选项匹配与实际选择仍需核验。没有引入 AI 或逐站大规模枚举。

## 埋点

新增固定数值指标 `controlDatePrecisionMissingCount`、`controlPopupCloseFailedCount`，已接入现有 fill result 埋点与服务端白名单。不上传具体日期、字段文案、简历内容或完整招聘 URL。
本轮本地服务日志可见插件 analytics 请求返回 204；这只验证到 Next 接收接口，不代表已查询 Java 统计服务最终入库。最终统计查询未覆盖。

## 剩余限制与下一步

- 淘天 20 个日期仍待处理：年月不足以确定具体日，“至今”也不能擅自变成结束日期。本轮没有新增默认日期策略或修改用户简历日期。完整年月日的日历驱动仅通过受控组件自动化样例，尚未以用户实际日精度资料验证淘天端到端。
- 腾讯还有当前资料缺项/未映射选项，并非整个页面全部完成。
- 未从空白表单测试首次新增 4 条经历，也未验证保存或最终提交（用户明确禁止）。
- 结论：本轮已实测修复腾讯结束日期、淘天期望城市、日历弹层残留与侧栏串页；不能把它当成腾讯/淘天完整表单或所有招聘网站的上线验收。
