# 导出场景终身会员推荐与月会员轻提示

策略版本：`monthly-v1`。PC 编辑器导出预览和小程序 H5 导出预览启用；其他会员入口不传 retention 参数，保留原行为。小程序原生支付仍使用已有 checkout 链路，本次不改变商品、定价、订单或权益。

## 行为

- 按用户最新要求，套餐固定排列为终身会员 → 年会员 → 月会员，首次默认选中终身会员，并显示“推荐开通”；缺失或停用的套餐跳过。同一次预览保留手动选择。轻提示入口指定选中月会员，但不改变排列顺序。小程序进入编辑首页即提前加载本端公开套餐，直接进入预览页时也会预加载，内存缓存最多 5 分钟，预加载与打开共用请求；过期后重新获取。月会员缺失/无效时不显示轻提示。
- 小程序已知额度耗尽时直接打开套餐，不再先请求确认导出并等待 402。未知或可用额度仍按原导出流程进行服务端校验。套餐缓存不参与订单定价，原生编辑/预览壳提前加载套餐，checkout 优先复用 5 分钟内的套餐；缓存缺失、过期或与显示价格不一致时刷新。支付签名接口继续使用服务端商品金额校验。
- 小程序会员弹窗上滑展开 300ms、下滑收起 240ms，关闭动画完成后卸载；跟随系统减少动画偏好。重新加载价格时保留已有卡片，加载失败禁用购买并提供重试。
- 主动关闭已加载的会员弹窗后，核验当前额度。只有当前付费格式仍无额度才显示提示，替换额度说明，不覆盖格式按钮。Markdown、模板不支持的 Word、已确认可重复下载的文件不会触发。
- 支付交接后的小程序返回、成功、加载失败、离开预览不触发挽留。成功刷新权益后仍需确认导出，不自动扣次或下载。
- localStorage 以策略版本、账号、端标识记录北京时间日期；在实际展示时占用当天次数。刷新/重进不重复，不跨设备同步；身份缺失或存储失败时关闭自动挽留。
- 账号识别优先采用 API 实际使用的 SSO Cookie 身份，兼容小程序没有 PC 登录资料的情况；额度请求、缓存和挽留频控使用同一身份来源，切换账号后丢弃旧请求结果。
- 预览生成中，已确认额度耗尽时可以打开会员套餐；额度未知或恢复会员后，实际导出仍需等正式预览加载完成并手动确认。等待区域固定展示真实阶段和已等待时间，从用户提供的 20 条原文中随机选取 5 条不重复提示，每 10 秒循环切换，不读取简历内容、不增加请求。支持左右滑动和前后按钮，手动操作后暂停，可继续自动轮播；页面隐藏、鼠标悬停时暂缓，减少动态效果偏好下默认暂停。小屏下缩紧卡片，保持进度和底部操作可见。提示文案按用户原文保留，不改写。
- 关闭回调与异步额度请求使用请求序号及账号校验，离开、切换账号或恢复权益后丢弃旧结果。再次查看月会员也先核验权益，失败不打开付款页。
- `refreshQuota()` 返回新鲜 `VipQuotaStatus` 或 `null`。失败时仍可用缓存显示原界面，但不会把缓存当作成功核验。请求和缓存均按账号隔离。

## 开关与回退

套餐预加载已提前到小程序编辑首页（`/m/edit`）挂载时，异步请求不阻塞编辑。编辑页和预览弹窗共用 H5 模块内的 5 分钟缓存及并发请求；通过客户端路由进入预览时复用。直接进入预览仍保留原预加载作为兜底。尚未完成、失败或过期时打开弹窗仍可能需要等待，不承诺任意网络环境下零等待。

`NEXT_PUBLIC_EXPORT_RETENTION_ENABLED=false` 关闭导出场景的推荐覆盖和轻提示，恢复已有入口规则。默认启用，全量展示，不做实验分流。这是 Next.js **构建时开关**，生产回退需重新构建发布，或回退到先前已验证版本；修改运行时环境变量不能改变已有前端包。本次仅本地实现，尚未发布。

## 事件与观察口径

沿用服务端允许的事件名，不需要数据库迁移或新增事件白名单：

| 行为 | 事件及区分字段 |
| --- | --- |
| 原导出会员弹窗曝光 | `export_paywall_view`，entry 为 `vip_upgrade_dialog` 或 `mini_export_membership_sheet`，携带推荐套餐和策略版本 |
| 轻提示曝光 | `export_paywall_view`，`entry=export_retention_card`、`action=retention_view` |
| 轻提示打开月会员 | `paywall_cta_click`，`entry=export_retention_card`、`action=view_monthly` |
| 轻提示拒绝 | `paywall_close`，`entry=export_retention_card`、`action=retention_dismiss` |
| 原生支付/扫码支付及导出 | 沿用现有事件与订单结果，不新增扣费或成功判定 |

统计原会员弹窗人数时排除 `entry=export_retention_card`，避免把轻提示曝光算成第二次弹窗。分 PC、小程序、同一北京时间日历口径，对比上线前后完整七天：

- 付款率：曝光账号中，首次曝光后 24 小时内有服务端确认成功订单的账号数 / 曝光账号数。
- 每曝光用户实收：同一归因窗口订单实收减退款 / 曝光账号数；订单号去重，后续退款回补。
- 套餐构成：成功订单按月/年/终身分布。
- 提示点击后付款：点击账号在 24 小时内的付款比例；不能据此认定增量收入。
- 付款后导出：付款账号 24 小时内 `export_success` 比例，区分生成文件与实际下载事件。

跨端订单按已有订单 source 和账号归属统计；前后对比不作为因果证明。发现支付、权益、导出回归即回退版本。真实收入以服务端订单为准，不能使用客户端 `pay_success` 事件累加金额。
